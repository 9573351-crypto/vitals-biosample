## 生息样本库 1.19.2 · 修复自动更新不可用

### 问题现象

点击侧边栏「检查更新」检测不到新版本，一键更新实际不可用。

### 三个根因

1. **v1.18.2 的发布资产不含更新模块**：它是打包方提供的原始 APK，里面没有 `updater.js` / `VitalsUpdater`，因此没有检测能力。
2. **当时没有比 1.18.2 更新的版本**：最新 Release 与本机版本相同，即使有模块也只会显示「已是最新」。
3. **下载地址白名单过窄（致命）**：GitHub 的 Release 资产下载现在跳转到 `release-assets.githubusercontent.com`，而白名单里只有旧的 `objects.githubusercontent.com`，真实下载必然在重定向处被拦下。

### 修复内容

- **下载**：白名单补齐实际跳转目标；新增「API 直链 + 浏览器下载地址」双候选与最多 3 次重试（指数退避）；读超时由 20 秒放宽至 90 秒。
- **版本显示**：原生在 `checking` / `checked` 事件中直接带回本机版本，不再依赖同步桥；桥不可用时依次回退到界面构建标记与页面自报版本。
- **错误可诊断**：区分超时 / DNS / TLS / 连接被拦截 / GitHub 限流，并写入日志（tag `VitalsUpdate`）。
- **安装前签名校验**：签名不一致时直接提示「请先导出备份后卸载旧版本再安装」，而不是让系统只报「应用未安装」。

### 同时包含（来自协作者的 1.19.0 工作）

- 「一体机内部自动备份」设置卡片：授权内部存储目录后，数据变更 5 秒防抖生成完整 JSON 备份，启动时超过 24 小时未备份自动补做，保留最近 30 份，可随时立即备份或关闭（关闭不删文件）。
- 最新温度逻辑：预警需持续 3 秒才切换，告警记录冷却 3 秒；7 天后仅清理正常温度聚合桶，异常时段继续保留并设安全上限。

### 安装须知

- **签名**：本 APK 使用构建方的调试签名。若设备上已安装的版本来自打包方原始 APK，两者签名不同，**无法直接覆盖安装**：请先在「设置」中导出备份（或使用内部自动备份），卸载旧版后再安装本包。应用会在交给系统安装器之前自动检查并提示该情况。
- 从本版开始，只要后续 Release 始终使用同一签名，即可在应用内一键升级。
- 卸载会清除本机数据，操作前请先备份。
