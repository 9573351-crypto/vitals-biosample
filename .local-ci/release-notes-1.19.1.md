## 生息样本库 1.19.1 · 修复自动更新不可用

### 问题现象

点击侧边栏「检查更新」检测不到新版本，一键更新实际不可用。

### 三个根因

1. **v1.18.2 的发布资产不含更新模块**：它是打包方提供的原始 APK，里面没有 `updater.js` / `VitalsUpdater`，所以没有检测能力。
2. **当时没有更新版本**：最新 Release 就是 1.18.2，与本机版本相同，即使有模块也只会显示「已是最新」。
3. **下载地址白名单过窄（致命）**：GitHub 的 Release 资产下载现在跳转到 `release-assets.githubusercontent.com`，而白名单里只有旧的 `objects.githubusercontent.com`，导致真实下载必然在重定向处被拦下。

### 修复内容

- **下载**：白名单补齐实际跳转目标；新增「API 直链 + 浏览器下载地址」双候选与最多 3 次重试（指数退避）；读超时由 20 秒放宽至 90 秒，避免国内网络下大包必然超时。
- **版本显示**：原生在 `checking` / `checked` 事件中直接带回本机版本，不再依赖同步桥；桥不可用时依次回退到界面构建标记与页面自报版本，避免「当前版本未知」被误判为检测失败。
- **错误可诊断**：区分超时 / DNS / TLS / 连接被拦截 / GitHub 限流，并写入日志（tag `VitalsUpdate`）。
- **安装前签名校验**：签名不一致时直接提示「请先导出备份后卸载旧版本再安装」，而不是让系统只报「应用未安装」。
- `build-apk.ps1` 版本号改为从 `app/build.gradle` 读取。

### 验证结果

- `tools/updater.test.mjs`：45 项行为断言全部通过。
- 以真实 GitHub API 驱动原生 `VitalsUpdater`：
  - 模拟 1.18.2 设备：**25/25 通过** —— 正确检测到 1.19.x，解析资产，真实下载 2.7 MB，SHA-256 与 Release 摘要一致，包名与完整性校验通过，签名不一致时给出可读提示；
  - 模拟 1.19.0 设备：正确返回「无更新」，无误报。
- APK 内已确认包含 `release-assets.githubusercontent.com` 白名单（DEX 校验）与 `assets/web/updater.js`、`res/xml/file_provider` 配置。

### 安装须知

- **签名**：本 APK 使用本机构建调试签名。若设备上已安装的版本来自打包方原始 APK，两者签名不同，**无法直接覆盖安装**：请先在「设置」中导出备份，卸载旧版后再安装本包。安装后应用会在交给系统安装器之前自动检查并提示该情况。
- 从本版开始，只要后续 Release 始终使用同一签名，即可在应用内一键升级。
- 卸载会清除本机数据，操作前请先导出备份。
