# 第三组 ↔ 第二组／第四组 USB 串口协议草案

必须先由各组确认并在单片机端实现，再启用界面的硬件联调模式。当前没有硬件实测。

## 通用设置

UTF-8 文本，每条消息以换行 `\n` 结尾（也接受 CRLF）。默认 115200 baud、8 数据位、无校验、1 停止位；可在界面选择 9600 或 57600。每个设备独立接收缓冲，支持拆包和粘包，超长行丢弃。

## 机械板

第三组发送：

```text
IN,A-0,SB-001
```

三个字段依次为：

1. 出入库指示：`IN` 入库，`OUT` 出库。
2. `样本种类-圆槽位置`：种类编码为 A=全血、B=血清、C=血浆、D=DNA、E=RNA、F=尿液、G=组织切片、H=其他；实体圆槽 1—5 依次发送为 0—4，不补零，例如圆槽 1 为 `A-0`、圆槽 5 为 `A-4`。
3. 样本 ID：例如 `SB-001`。

圆槽位置为固定圆盘槽号 0—4，不是角度。第二组确定零点、入出口位置、运动方向和槽号到角度的换算。指令的具体机械过程由双方约定。

第二组反馈（使用收到的同一样本 ID）：

```text
ACCEPTED,SB-001
ARRIVED,SB-001
```

无位置反馈、仅时间估算时：

```text
ESTIMATED,SB-001
```

失败时：

```text
FAILED,SB-001,电机未回零
```

- `accepted` 只表示已接收，不改变库存。
- `arrived` 且 `feedback: position` 表示位置反馈到位；仍需人工确认样本已放好／拿走。
- `estimated` 或未声明位置反馈的 arrived 均要求人工核实位置。
- 指令提交后 30 秒内无有效到位结果，进入待核实状态。此超时不表示机械已停止。
- 第二组应避免重复执行同一样本的未完成指令。第三组不会自动重发。
- App 仍兼容旧版 JSON 回执，便于机械板固件过渡；新固件应使用上述文本回执。
- 同一时刻只允许一项圆盘任务；断线、失败、重启后不自动释放任务占用。
- App 内“核实未完成”只是记录处理，不会发送急停。实物急停及保护由硬件组实现。

## 温控板

保留原项目格式：

```json
{"t":4.2,"l":320,"id":"SB-实际内部样本编号"}
```

字段 `t/l` 分别为温度和光照；旧设备发送的 `h` 字段会被忽略；`id` 为应用内部样本 id。原程序在不带 id 时仅选择第一个开启监控的样本；不要假设会广播所有样本。界面导出的 JSON 包含实际 id。

温控模拟器必须先断开真实温控串口后使用，以避免混合演示和真实读数。
