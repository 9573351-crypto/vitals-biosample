# 生息样本库 · 安卓迁移版

## 1.19.0 一体机内部自动备份

设置页新增「一体机内部自动备份」。首次使用时在 Android 系统目录选择器中选择一体机内部存储目录；以后样本、记录或设置成功变更后，应用会在 5 秒防抖后生成完整 JSON 备份。应用启动且距离上次成功备份超过 24 小时时会自动补做一次，目录内只保留最近 30 份。可随时立即备份或关闭自动备份，关闭不会删除已有文件，不需要 U 盘。

温度预警采用 EMA 平滑与持续 3 秒去抖，告警记录冷却为 3 秒。正常温度追溯保留 7 天；异常分钟聚合桶在 7 天后继续保留，并设置单样本 130000 桶安全上限，防止无限增长。

## 1.18.2 人工出库免扫码

人工模式出库移除扫码核对步骤，只需人工取出样本、勾选“我已核实样本已取出”并确认完成。硬件模式收到有效 `OK` 后自动出库；硬件模式进入到位或待核实状态时仍保留扫码核对，避免机械操作对象与任务样本不一致。

## 1.18.1 精简扫码入口

样本库移除单独的“扫码枪录入样本”按钮，保留“扫码枪查询样本”。扫码录入能力仍完整保留：打开“录入样本”后可使用样本编号旁的“扫码枪扫描编号”，扫码解析、自动填号、重复编号识别以及内部 `new` 模式均保持可用。

## 1.18.0 分类温度追溯

合并 `D:\sx\版本\vitals-android` 的温度改动：B1 全血、B2 血清、B3 血浆分别显示适宜温度范围 `30—65℃`、`25—65℃`、`25—60℃`。串口温度使用 EMA 平滑和连续 5 次采样去抖，告警记录设置 10 秒冷却；原始温度点保留 30 分钟，较早数据按 1 分钟聚合，总追溯期为 7 天。删除样本时同步删除对应温度追溯数据。

## 1.17.0 录入时预选位置

“录入样本”表单中的存放位置由自由文本改为 `1—5` 号下拉框。选择全血、血清或血浆时会查询对应圆盘的占用和其他待入库样本的预选情况，自动填入第一个空位，也可以手动选择其他空位。保存后保留预选位置，执行入库时优先使用；完成入库后转为实际占用位置。

## 1.16.0 自动匹配空余位置

圆盘孔位直接显示 `1—5`，不再显示 `0→1` 形式。发起入库时根据样本类别查询对应圆盘的占用状态，自动填选第一个空余位置；操作人员仍可在下拉框或圆盘上改选其他空位。界面位置统一显示 `1—5`，发送给机械板的协议位置继续转换为 `0—4`。

## 1.15.0 透明圆盘俯视图

三个样本圆盘改为透明亚克力质感的俯视图，盘面直接标出 `A-全血`、`B-血清`、`C-血浆`。每个圆孔显示机械编号到系统槽位的映射 `0→1` 至 `4→5`；空闲、占用、选中和任务处理中状态继续使用孔位图形区分，点击操作保持不变。

## 1.14.0 三路温度界面精简

合并 `D:\sx\vitals-android` 中的温度界面改动：移除与 B1/B2/B3 重复的“当前温度”大卡片，实时监测页保留三类样本的独立温度卡、对应范围、最近接收时间、数据格式及串口日志。温度解析、分类映射、告警和历史曲线逻辑保持不变。

## 1.13.0 三圆盘存储可视化

“样本库 → 出入库”以三个彩色圆盘显示全血、血清和血浆的存储状态，每盘五个环形槽位。图中不显示槽号、名称或图例文字：空心试管表示空闲，实心试管表示占用，脉冲槽位表示任务处理中。点击空槽可直接选择入库位置，点击占用槽可打开对应样本详情。

## 1.12.0 三类样本独立圆盘

全血、血清、血浆分别对应 A、B、C 三个圆盘，每个圆盘独立使用 0—4 号五个槽位，总容量 15。同一槽号可以在不同圆盘同时占用，同一圆盘内仍禁止重复占用。入库时按样本类型自动选择对应圆盘，位置显示为“全血圆盘 0号”等；机械指令保持 `IN/OUT,A-C-0-4` 两段格式。

数据库 schema 升至 3，将槽位唯一约束从全库单一槽号改为“样本类型 + 槽位”。覆盖升级会保留原样本、记录、设置和未完成任务；备份导入与原生事务校验同步采用三圆盘规则。

## 1.11.0 样本库整合出入库

侧边栏不再单独显示“出入库”。“样本库”页面内使用“样本列表 / 出入库”两个按钮切换，原五槽位选择、任务状态、人工确认及机械指令流程保持不变；从样本行发起操作时会直接打开样本库内的出入库面板。

## 1.10.0 出入库与机械连接分离

侧边栏新增与“概览、样本库、设备连接”同级的“出入库”页面，五槽位选择、任务状态和人工操作集中于该页面；设备连接页只负责机械板的连接、断开与 STM32 串口调试。

硬件出库发送 `OUT,类别-槽位` 后，机械板返回 `OK`、`ok=1`、`ok=true` 或 `{"ok":true}` 即自动完成当前出库、释放槽位并写入动态记录。带样本号的 `OK,样本号` 必须与当前任务一致；超时、重启后的待核实任务及无活动任务不会被延迟反馈自动出库。硬件入库仍需人工确认样本已放好。

## 1.9.0 设备集中连接

侧边栏新增与“概览、样本库”同级的“设备连接”页面，集中放置温度板、得力 AA307 扫码枪、STM32 机械板及得力标签打印机的连接状态和控制。概览“设备在线”卡片及顶部“连接设备”按钮均可直接跳转；样本库保留扫码业务按钮，实时监测页保留温度显示、排架状态和曲线。

## 1.8.0 温度串口实时显示

实时监测页新增温度串口可视化面板，显示连接状态、B1/B2/B3 三路温度、最近接收时间、解析格式及最近 100 条原始数据。温度板协议 `B1 T=27.50`、`B2 T=27.00`、`B3 T=27.00` 分别映射 A类（全血）、B类（血清）、C类（血浆），同类别所有在库样本共享该路温度并分别写入曲线。另兼容 JSON（`{"t":25.3}` 或 `{"temp":25.3}`）、`temp=25.3`、`T:25.3` 和单独数值 `25.3`。

## 1.7.1 AA307 中文二维码兼容

AA307 可以解码原有 QR Code；故障来自旧二维码包含多行中文详情，扫码枪经虚拟串口输出时发生字符集转换，应用收到乱码前缀并把多行误判成多次扫描。本版保留旧标签兼容：按扫码数据突发及短暂空闲识别完整的一次扫描，不再用二维码内部换行拆分消息，并从乱码文本中提取已有编号或 `SB-...` 编号。

新生成及新打印的二维码只编码 ASCII 样本编号，名称和其他信息继续印在标签文字区，从源头避免乱码并降低二维码密度。AA307 保持“USB 虚拟串口功能”即可；回车、换行、回车换行及不添加结束符均由接收端统一兼容。

## 1.7.0 得力 AA307 USB 扫码枪

摄像头扫码、拍照入口和相机权限已移除，样本查询、编号录入及出库核对改用得力 AA307 二维条码扫描器。应用按 `152A:880F / VSerial` 独立识别扫码枪，不与温控板或 STM32 串口混用；在样本库连接后再选择对应扫码功能。

扫码枪需设置为“USB 虚拟串口功能”，并使用回车、换行或回车换行结束符。应用按完整的一行处理一次扫码；“禁止添加结束符”模式无法判断一次扫码何时结束。原有本地图片上传仍可用于保存样本照片。

## 1.6.4 两段机械指令

当前 STM32 联调阶段只发送动作和样本种类／圆槽位置，例如 `IN,A-0`。串口调试面板及自动出入库流程均不再附加样本 ID。

## 1.6.3 STM32 串口调试

修复 Android 12 上 CH340 USB 授权结果无法返回应用的问题。实时监测页新增 STM32 串口调试面板，可视化生成并发送 `IN,A-0,SB-001` 格式的三段机械指令，并显示发送、接收和错误日志。

## 1.6.2 圆槽发送编号

实体圆槽 1—5 对应串口编号 0—4，编号不补零：圆槽 1 发送 `A-0`，圆槽 5 发送 `A-4`。

## 1.6.1 圆槽编号 0—4

界面和机械串口中的五个圆槽显示为 0—4。

## 1.6.0 三段机械串口协议

机械板指令采用 `IN/OUT,样本种类-圆槽位置,样本ID`，例如 `IN,A-0,SB-001`。样本种类按界面顺序固定映射为 A—H；机械板可用 `ACCEPTED,样本ID`、`ARRIVED,样本ID`、`ESTIMATED,样本ID` 或 `FAILED,样本ID,原因` 回执。

## 安装与运行

1. 将 `output/Vitals-Android-1.1.1.apk` 复制到安卓设备，允许文件管理器安装此来源的应用，安装“生息样本库”。包名与签名不变，可覆盖升级 1.0.0 / 1.1.0；不要先卸载。
2. 支持 Android 8.0 及以上，面向 Android 12 触控一体机。无需原电脑、Node 服务或网络。
3. 此 APK 为开发测试签名版本，适用于本项目联调。后续升级需使用相同签名和包名；卸载或清除应用数据会删除本机数据库，请先导出。
4. 使用得力 AA307 USB 扫码枪扫描二维码：支持查询、录入编号和出库核对；录入表单仍可手动填写样本信息。设备间同步不在此版范围内。

1.1.1 修复保存冲突后旧任务状态覆盖数据库最新结果的问题；温度阈值支持 0，先校验上下限，数据库保存失败时不会提示成功。数据库 schema 仍为版本 2。详见 [后续联调报告](docs/INTEGRATION-1.1.1.md)。

## 保留与迁移

- 保留原有概览、样本表单、照片、二维码、温度图表、监控和记录界面。
- 在安卓副本修复原 app.js 缺少闭合括号、导航块被误注释的问题，并补齐原目录缺少的图表与二维码库。
- 数据在应用私有目录 `databases/vitals.db`，由 `VitalsDbHelper`（SQLiteOpenHelper，版本 3）管理 `samples`、`records`、`settings`。SQLite 是持久化数据源，JS `state` 仅为运行时 ViewModel。
- `samples` 保存样本主体，`records.sample_id → samples.sample_id` 为 1:N 外键。删除样本时历史记录保留，关联改为 NULL；旧记录仅在名称唯一匹配时关联，不猜测同名样本。
- 旧 `app_state` 仅作 legacy 兼容保留，不再写入。首次升级在事务内迁移版本 0/1 的旧 payload；完成标记存在 `db_meta`，清空数据后也不会重复迁移。若旧数据有重复条码／槽位等冲突，会回滚并提示，绝不静默删除原数据。
- 主要字段为独立列；照片仍以 Base64 TEXT 保存，`env` 等复杂／未知字段保存在 `extra_json`。未来大量照片建议迁移到文件存储＋SQLite 路径，本次不改变照片格式。
- 原程序本机 localStorage 数据不在源代码文件夹中，不能仅复制源码带走真实数据。
- 在原运行程序点击“导出”，把 JSON 复制到安卓设备，在安卓版“导入”中选取文件。支持 `{s,rec,set}` 完整 state、`{samples,records,settings}` 旧／新备份、纯样本对象或数组。全量导入使用原生事务，全部成功才刷新界面；导出从三张正式表组装兼容 JSON。
- 导入前验证重复条码、同类圆盘槽位冲突、字段类型和照片格式；待处理机械任务备份禁止直接跨设备恢复。
- 初次安装为空库，无虚拟样本。测试图中的数据不会预装到 APK。
- 新录入样本尚未入库（内部 `status: out`）；先录入，再点击入库完成实物流程。

## 三圆盘与组间分工

第三组：识别样本、选择槽位、下发任务、展示反馈、人工确认后保存库存。第二组：驱动电机、回零与角度换算、判断到位、反馈异常。

“样本库 → 出入库”先按样本类型选择全血、血清或血浆圆盘，再选择圆盘内的 0—4 号槽位。旧数据的 `A-01-03` 等位置不会自动猜成圆盘槽位，使用“绑定已有在库样本槽位”进行人工核实绑定。

默认人工模式，不发送电机指令。接好机械板并与第二组确认协议后，可选择“硬件联调模式”。系统同时只允许一项机械任务；重启、超时、断线后保持库存不变并要求人工核实，绝不自动重发运动指令。

出库必须核对样本编号并确认拿走；入库必须确认位置及样本放好。任务取消不等于电机停止，须先由操作人员停止机械并恢复操作前的实物状态。

## 设备连接

- 两路 USB 串口连接分别负责温控和机械。支持库识别的 CH340、CP210x、FTDI、CDC/ACM 等设备，实际兼容性需要用具体芯片和固件实测。
- 选择波特率，8N1；点连接时选择设备并允许 USB 权限。同一 USB 设备不同时分配给两个用途。
- 不使用 Web Serial；数据由安卓 USB Host API 及 vendored USB 串口驱动传入界面。
- 内置 DB9/RS232 的设备节点接口尚未接入，需厂家 SDK、引脚和权限资料；不能把板上 TTL 引脚直接当 RS232 接。
- App 前台运行时保持屏幕常亮。未实现开机自动启动、后台长期采集或系统级 kiosk 锁定。
- 打印调用安卓系统打印服务／保存 PDF；USB 标签打印机需要设备自己的兼容打印服务或另外适配。

见 [通信协议](docs/PROTOCOL.md)，目前是可测试的协议草案，不代表硬件已经采用。

## 开发

用 Android Studio 打开本目录。界面代码：`app/src/main/assets/web/`；原生 Bridge、USB、文件和打印仍在 `MainActivity.java`；数据库建表／升级／查询／事务在同目录 `VitalsDbHelper.java`。`persistence.js` 将数据库数据转换成原有 state，并只提交改变的样本、追加记录及设置差异，不发送整个 state。

## 数据库结构

| 表 | 主要列与约束 |
|---|---|
| samples | sample_id 主键；name；barcode（映射 JS code，非空值唯一）；status 仅 in/out；slot 为 1—5 或 NULL 且唯一；last_slot；pending_intake；类型、位置、采集时间、温度、备注、照片、创建／更新时间、监控、最近读数、报警、二维码快照；extra_json |
| records | id 自增主键；sample_id 可空外键；sample_name/time/type/detail 保留原四字段；barcode/slot/status/task_id 保存新操作快照；extra_json |
| settings | key 主键；value 为对应设置值的 JSON 文本，包括 hi/lo/simOn/online/motionTask 和扩展设置 |
| db_meta | 数据库内部迁移标记、版本冲突检查 revision、旧 state.s 扩展元信息，不存整库业务快照 |

出库后的当前 slot 为 NULL，历史槽位存 last_slot。只有唯一名称匹配的旧记录才能推断 sample_id，其他记录保留名称且外键为空。正式 DDL 与全部字段映射见 [字段审计](docs/SCHEMA-AUDIT.md) 和 [最终报告](docs/SCHEMA-REFACTOR-REPORT.md)。

正常采样即时刷新曲线，最近读数及有界历史约每 2 秒合并持久化；异常转换和人工操作立即提交。不会把每个串口字节或每个普通采样新增为 records。突然断电可能丢失最后约 2 秒尚未提交的普通读数；已提交的库存／任务不受此合并影响。

本机已配置 JDK 与 Android SDK，可执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\build-apk.ps1
node --test .\tools\test-core.cjs
node .\tools\test-ui.cjs
powershell -ExecutionPolicy Bypass -File .\tools\test-db.ps1
node .\tools\test-android-preserved.cjs
```

其他电脑请调整 `local.properties` 和构建脚本中的 JDK 路径。Gradle wrapper 9.3.1，AGP 9.1.0，compileSdk 36，targetSdk 34。Google Play 上架不在本次范围。

后两项需先启动 emulator-5554。数据库测试使用独立测试 DB，界面测试包装器会备份并恢复模拟器原数据库。不要直接对有重要数据的模拟器执行旧 `test-android.cjs`，请用 preserved 包装器。

`tools/migrate.cjs` 和 `tools/refactor-persistence.cjs` 仅记录一次性源码改造过程，不要在已修改副本上反复运行。安装后的数据库升级由 VitalsDbHelper 自动执行，不依赖这些脚本。

## 开发约定

### 1. 两份前端副本必须同步

同一套前端同时存在两处，除白名单外必须逐字节一致：

- `app/src/main/assets/web/`（随 APK 打包）
- 仓库根目录的 `web-preview/`（浏览器预览版）

```powershell
cd ..
node vitals-android/tools/sync-assets.mjs          # 校验；有差异时退出码 1，输出「文件: 差异类型」
node vitals-android/tools/sync-assets.mjs --fix    # 用 assets 侧覆盖 web-preview 侧的白名单外文件
```

白名单（允许不同）：`index.html`、`web-bridge.js`、`web-preview.css`、`.update-styles.tmp.css`。
`web-preview/tools/`（如 `verify-preview.mjs`）是预览专属工具目录，不参与比较。

### 2. 桥契约变更必须同时改三处

`MainActivity.java` / `VitalsDbHelper.java` 中 `@JavascriptInterface` 的签名一旦变更（新增、改名、参数或返回结构变化），必须同步：

1. 原生实现（`MainActivity.java` / `VitalsDbHelper.java`）；
2. 两份前端副本（`app/src/main/assets/web` 与 `web-preview`，含所有调用点与 `persistence.js`）；
3. 数据字典 [docs/DATA-DICTIONARY.md](docs/DATA-DICTIONARY.md)——列定义、枚举值、时间格式与桥方法映射。

新增 `samples` / `records` 列时，除了 DDL 还要同步 `VitalsDbHelper` 内的 `JS[]` / `SQL[]` 映射数组，否则字段会落进 `extra_json`。

### 3. 测试工具的路径自动推导

- `tools/test-ui.cjs`：playwright 依次尝试 `PLAYWRIGHT_PATH`、`require.resolve('playwright')`、常见缓存与全局目录；全部失败时打印提示并以退出码 0 跳过，不阻塞其他测试。
- `tools/test-android.cjs` / `tools/test-db.ps1`：`adb` 从 `ANDROID_HOME` / `ANDROID_SDK_ROOT` / 本目录 `local.properties` 的 `sdk.dir` 推导，找不到时给出可读提示；不再需要改脚本常量。
- `.ps1` 一律保存为 **UTF-8 with BOM**：Windows PowerShell 5.1 会把无 BOM 的 UTF-8 当 ANSI 读取，中文注释与提示可能导致解析失败（`test-db.ps1`、`build-apk.ps1`、`release.ps1` 均适用）。

### 4. 发版流程

```powershell
cd vitals-android
powershell -ExecutionPolicy Bypass -File .\build-apk.ps1   # 构建 → output\Vitals-Android-<版本>.apk
cd ..
.\release.ps1                                             # 读取 versionName，构建并发布到 GitHub Release
.\release.ps1 -SkipBuild                                  # 只上传已有 APK
```

发布前先跑 `cd vitals-android; node tools\sync-assets.mjs`、`node tools\updater.test.mjs`、`node tools\test-core.cjs`。
版本号只改 `app/build.gradle` 的 `versionName` / `versionCode`；Release 资产名必须是 `Vitals-Android-<versionName>.apk`。
